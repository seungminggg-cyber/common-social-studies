# 개념 강의 영상 자료 (판서 화면 + 녹음 + 영상)

판서가 한 단계씩 나타나는 강의 화면을 만들고, 강사가 화면을 넘기며 목소리만 녹음하면
그 녹음에 맞춰 판서가 움직이는 강의 영상(mp4)을 만든다.
첫 견본: **사회와 문화 Ⅰ-2 사회·문화 현상의 탐구 방법** (4강, 화면 28장, 판서 170단계).

## 강사가 쓰는 법
1. `강의화면.html`을 **크롬이나 엣지로 연다** (파일을 더블클릭하거나 브라우저 창에 끌어 놓기).
2. 발표처럼 보기: → 키(또는 화면 클릭)로 판서가 하나씩 나타나고, ← 키로 되돌린다. `F` 전체 화면, `T` 차례.
3. `N`을 누르면 오른쪽에 **녹음 메모**가 나온다. 지금 단계에서 할 말이 파랗게 표시된다.
4. `R`을 누르면 **녹음 모드**가 된다. 다시 `R`을 누르면 3·2·1 뒤에 녹음이 시작된다.
   - → 키로 판서를 넘기며 말한다. 마지막 판서에서 → 를 누르면 그 화면 녹음이 끝나고 다음 화면 녹음이 바로 이어진다.
   - 틀리면 `R`로 멈추고 그 화면에서 다시 `R`. 그 화면 녹음만 바뀐다.
   - ‘이 화면 들어보기’로 판서와 목소리가 맞는지 바로 확인할 수 있다.
   - 녹음은 브라우저 안에 보관되어 창을 닫았다 열어도 남아 있다 (다른 컴퓨터로 옮기려면 저장한 파일을 ‘불러오기’).
5. 다 녹음하면 **‘녹음 파일 저장’** → 생긴 `.json` 파일을 Claude에게 보내면 강마다 영상(mp4)을 만들어 준다.

메모의 `[사례를 소리 내어 읽어 주세요]`처럼 대괄호 안은 할 일 안내다.

## 결과물 (`out/<강의id>/`, 저장소에는 올리지 않음)
| 파일 | 내용 |
|---|---|
| `강의화면.html` | 발표·메모·녹음 화면 (글꼴까지 들어 있어 이 파일 하나로 동작) |
| `artifact.html` | 같은 화면을 claude.ai 페이지로 올릴 때 쓰는 판 (녹음은 안 됨) |
| `판서노트_학생용.pdf` | 화면 2장씩, 빈칸·O/X 정답을 비운 판서 노트 (영상 보며 채우기) |
| `판서노트_교사용.pdf` | 같은 노트, 다 채운 것 |
| `녹음메모.pdf` | 화면 1장마다 판서 그림 + 단계별로 할 말 (종이로 보며 녹음할 때) |
| `png/` | 확인용 화면 그림 (`png` 옵션) |
| `영상/<n>강_<제목>.mp4` | `make-video.mjs` 결과 (1920×1080, 30fps) |

## 만드는 법 (Claude용)
```bash
cd textbook && npm install && cd ..        # 글꼴(Pretendard·KoPub)이 textbook/node_modules에 있음
pip install fonttools brotli               # 글꼴에서 쓰는 글자만 뽑기 (pyftsubset)
node 강의자료/build.mjs sm-1-2             # 강의화면.html + PDF 3개
node 강의자료/build.mjs sm-1-2 png nopdf   # 화면 그림만 (넘치는 화면 검사도 같이)
node 강의자료/make-video.mjs <녹음파일.json> [강 번호…] [--partial] [--no-anim]
```
- 손글씨 글꼴(나눔손글씨 펜, OFL)은 처음 만들 때 Google Fonts 저장소(raw.githubusercontent.com)에서 받아 `.cache/`에 둔다.
- 영상: 녹음 때 → 를 누른 시각대로 판서가 나타나고, 그어지는 움직임(0.66초)은 1/30초씩 찍어 넣는다.
  소리는 이어 붙인 뒤 낮은 웅웅 소리 거르기·약한 잡음 줄이기·음량 맞추기(loudnorm −16 LUFS)를 한다.
  8분짜리 강 하나에 2~3분 걸린다. `--no-anim`이면 더 빠르다.

## 내용 쓰는 법 (`content/<id>.js`)
- 강(`lectures`) → 화면(`slides`). 화면마다 `tag`(개념·도입·비교·함정·연습·자료·확인·정리), `title`, `body`, `memo`.
- 표지는 `kind: 'cover'`, `today`(오늘 배울 것 목록, 하나씩 나타남).
- `body`의 판서는 `lib/dsl.js` 도우미로 쓴다. 첫 인자 = 몇 번째 단계에 나타나는지.
  `S` 덩어리, `I` 글자 일부, `B` 빈칸(파란 펜으로 채워짐·학생용 노트에서는 빈칸), `HL` 형광펜, `UL` 밑줄,
  `CI` 동그라미, `H` 빨간 손글씨, `LB` 밑줄+이름표(사례 분석), `O`/`X` 도장,
  `ln` 이름표 줄, `pm` 장점·한계, `flow` 흐름도, `oxList` O·X 문제, `traps` 함정 문장, `bars` 막대그래프, `popDiagram` 모집단·표본 그림.
- **`memo` 개수 = 판서 단계 수 + 1** (0번은 화면이 처음 열렸을 때). 안 맞으면 build가 멈추고 알려 준다.
- 문장은 교과서를 옮기지 않고 새로 쓴다. 사례·수치는 가상이라고 밝힌다.
- 교과서마다 다른 곳(조작적 정의가 어느 단계인지, 단계 이름)은 화면·메모에 ‘우리 학교 교과서 확인’을 넣었다.

## 견본(sm-1-2) 검수
별도 에이전트가 사회·문화 교사 관점에서 검수함 (2026-11-18). 고친 것:
- 문헌 연구법은 양적·질적 연구 모두에서 쓴다.
- ‘표본의 크기만 크면 대표성이 높다’로 바꿈 (그냥 ‘많으면’은 지나친 일반화).
- 변수 밑줄은 ‘스마트폰 사용 시간’까지만 (‘길수록’은 관계를 나타내는 말).
- 질적 연구의 가설은 ‘대체로’ 없음.
- 기각 = ‘예상한 관계가 나타나지 않음’.
- 3강 사례의 문제 제기와 가설을 맞춤.
- 4강 (가)에 조작적 정의가 보이게 함.
- 용어 통일(스마트폰, 표본의 크기, 해석주의).
