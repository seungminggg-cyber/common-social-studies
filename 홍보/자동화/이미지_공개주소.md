# 인스타그램 그림을 어디에 올려 둘까 (공개 주소)

인스타그램 API는 그림 파일을 직접 받지 않는다. **누구나 열 수 있는 인터넷 주소**를 알려 주면 인스타그램 서버가 그 주소에서 그림을 가져간다. 그래서 카드뉴스 JPEG를 잠깐 올려 둘 곳이 필요하다. (스레드도 그림 글은 같은 방식이다.)

## 지금 상황 (2026-11-28 확인)
- 저장소 `seungminggg-cyber/common-social-studies`는 **공개 저장소**다. 이미 `홍보/out/`의 카드뉴스 PNG도 올라가 있다.
- `raw.githubusercontent.com` 주소로 저장소 파일이 바로 열린다(시험해 봄: 200 응답).
- 앱 배포(GitHub Pages)는 `main` 브랜치의 앱 빌드 결과(`dist/`)만 올린다. 홍보 파일은 들어가지 않는다.

## 방법 비교

| 방법 | 주소 모양 | 장점 | 단점 | 앱 배포에 영향 |
|---|---|---|---|---|
| **① 저장소 raw 주소 (추천)** | `raw.githubusercontent.com/…/claude/promo/홍보/자동화/공개/cn01/01.jpg` | 지금 바로 됨, 돈·계정 0, push만 하면 끝 | 저장소가 공개일 때만 됨. GitHub가 '파일 보관용'이지 그림 서버는 아니라서 가끔 느릴 수 있음 | 없음 (`claude/promo` 브랜치) |
| ② jsDelivr(무료 CDN) | `cdn.jsdelivr.net/gh/seungminggg-cyber/common-social-studies@<커밋 번호>/홍보/자동화/공개/cn01/01.jpg` | ①과 같은 파일을 더 빠른 서버로 | 브랜치 이름에 `/`가 있어 커밋 번호로 적어야 함. 한 번 받은 그림을 오래 보관 | 없음 |
| ③ GitHub Pages에 함께 올리기 | `seungminggg-cyber.github.io/common-social-studies/promo/cn01/01.jpg` | 진짜 웹 주소, 가장 안정적 | `main` 배포 설정을 바꿔야 하고, 그림을 바꿀 때마다 앱이 다시 배포됨 | **있음** → 강사·조정 채팅 동의 필요 |
| ④ 다른 저장 서비스(Cloudflare R2, 구글 클라우드 저장소 등) | 서비스 주소 | 저장소가 비공개여도 됨 | 계정·카드 등록, 열쇠가 하나 더 늘어남 | 없음 |
| ⑤ 구글 드라이브 '링크 공유' | `drive.google.com/…` | 강사가 익숙함 | 인스타가 그림 대신 확인 화면(HTML)을 받아 실패하는 경우가 많음 → **쓰지 않음** | 없음 |

## 추천: ① raw 주소, 막히면 ②
- 게시 도구(`post.mjs insta cn01 --prepare`)가 JPEG를 `홍보/자동화/공개/cn01/01.jpg …`에 만든다. 파일 이름은 영문·숫자로 짧게 둔다.
- 그 폴더를 `claude/promo`에 push → 게시 도구가 주소가 열리는지 먼저 확인하고 게시한다(안 열리면 멈춤).
- 앱 배포와 상관없으므로 **앱에는 영향이 없다.**
- 인스타그램은 게시할 때 그림을 자기 서버로 복사해 간다. 게시가 끝난 뒤에는 공개 폴더 파일을 지워도 게시물은 남는다(지울 필요는 없음 — 이미 공개된 카드뉴스와 같은 그림).

## 주의
- 공개 폴더에는 **이미 공개해도 되는 그림만** 둔다. 평가원 원문 그림(강의용 특강 교재), 학생 이름·얼굴이 보이는 그림은 절대 넣지 않는다.
- **저장소를 나중에 비공개로 바꾸면 ①·②는 멈춘다.** 그때는 ③ 또는 ④로 옮긴다(게시 도구는 환경 변수 `PUBLIC_BASE` 하나로 주소를 바꿀 수 있게 만들어 둠).
- 실제 인스타 서버가 raw 주소를 잘 가져가는지는 **계정이 생긴 뒤 첫 게시 때 확인**한다. 안 되면 ②로 바로 바꾼다.
