# 주간 성과 보고서 설계 (계정이 생긴 뒤에 켬)

**목표**: 매주 월요일 아침, 지난주(월~일) 숫자를 한 장으로 받아 본다.
조회수보다 **저장·공유·프로필 방문·카카오 친구·상담 문의**를 먼저 본다 (전략 보고서 '조회수 대신 상담 문의 수' 절).

## 1. 무엇을 보나

| 단계 | 지표 | 채널 | 어떻게 모으나 |
|---|---|---|---|
| **결과** (맨 위) | 상담 문의 수, '어떻게 알게 됐나요?' 답(채널별), 체험·등록, 교재 판매 | 상담 | 강사 입력 |
| 행동 | 카카오톡 채널 친구 순증(추가 − 차단) | 카카오 | 강사 입력 (관리자센터 → 통계) |
| 행동 | 게시물에서 프로필로 온 수(profile_visits), 프로필 링크 누른 수(profile_links_taps), 팔로우 순증 | 인스타 | 자동 (인사이트 API. 계정 전체 '프로필 조회수'는 2025-01에 API에서 없어짐) |
| 행동 | 영상으로 늘어난 구독자(얻음 − 잃음) | 유튜브 | 자동 (Analytics API) |
| 관심 | 게시물별 **저장·공유**, 도달 대비 저장·공유 비율 | 인스타 | 자동 |
| 관심 | 평균 시청 시간, 평균 시청 비율, 공유 | 유튜브 | 자동 |
| 관심 | 답글·인용·리포스트 | 스레드 | 자동 (스레드 인사이트 API, 2~3개월 뒤) |
| 검색 | 블로그 방문자 수, 이웃 순증, 많이 본 글 3개 | 네이버 블로그 | 강사 입력 (블로그 관리 → 통계) |
| 참고만 | 팔로워 수, 총 조회수, 좋아요 | 전체 | 자동 — 맨 아래 작게 |

- 처음 석 달은 남과 비교하지 않고 **지난주·4주 평균과 비교**만 한다.
- 유튜브 조회수는 2025~2026년에 세는 방식이 바뀌어(재생이 시작되면 셈) 커 보일 수 있다는 주의 문구를 넣는다.
- 인스타 인사이트는 **팔로워 100명 미만이면 일부 지표가 비어** 나온다. 빈칸은 '아직 없음'으로 적는다.

## 2. 강사가 넣는 숫자 (API가 없는 것)
네이버 블로그·카카오 채널은 통계 API가 없다. 매주 **월요일 아침 2분**만 숫자를 넣는다.

방법 (강사가 편한 쪽을 고름):
- **가. 구글 시트 한 장 (추천)**: 강사 드라이브에 `승민T 주간 숫자` 시트를 만들어 두면, 예약 작업이 드라이브 연결로 읽는다. 칸: 주 시작일 | 블로그 방문자 | 블로그 이웃 순증 | 카카오 친구 순증 | 상담 문의 | 알게 된 경로(유튜브·인스타·블로그·카카오·지인·기타) | 메모
- 나. 이 채팅에 한 줄로: `블로그 820, 이웃 +6, 카카오 +4, 상담 2(블로그 1, 지인 1)`

상담 숫자는 **저장소(공개)에 적지 않는다.** 시트와 보고서는 강사 드라이브에만 둔다.

## 3. 자동으로 모으는 것 (공식 API)
| 채널 | 범위 | API |
|---|---|---|
| 인스타 | 계정: reach, views, profile_links_taps, follows_and_unfollows, accounts_engaged / 게시물별: reach, saved, shares, views, profile_visits, follows, likes, comments (숫자는 최대 48시간 늦게 반영) | Instagram Insights (`instagram_business_manage_insights` 권한) |
| 유튜브 | 채널·영상별: views, estimatedMinutesWatched, averageViewDuration, subscribersGained·Lost, likes, shares, comments | YouTube Analytics API v2 (`yt-analytics.readonly` + `youtube.readonly` 둘 다 필요) |
| 스레드 | 글별: 조회, 좋아요, 답글, 리포스트, 인용, 공유 / 계정: 팔로워 | Threads Insights (`threads_manage_insights`) |

- 인스타 인사이트는 최대 90일만 보관된다 → 매주 받은 숫자를 드라이브에 쌓아 두면 그 뒤에도 추세를 볼 수 있다.
- 게시물별 숫자는 `기록/게시기록.json`에 있는 게시물 ID로 찾는다.

## 4. 보고서 모양 (한 장)
1. **이번 주 한 줄 요약** (예: "상담 2건, 둘 다 블로그 글 보고 옴. 카드뉴스 cn02 저장 41회로 가장 높음")
2. 결과·행동 표: 이번 주 | 지난주 | 4주 평균 | 변화
3. 잘된 게시물 3개 (저장+공유 기준) — 왜 잘됐는지 한 줄씩
4. 덜 된 것 1~2개와 다음 주 제안 2~3개 (주제·올리는 시간·형식)
5. 토큰 상태 (만료 7일 전이면 맨 위에 빨간 줄)
6. 참고: 팔로워·총 조회수

받는 곳: 강사 구글 드라이브 `홍보 주간 보고` 폴더(드라이브 연결) + 이 채팅에 요약 3줄. (Artifact 페이지로 보여 주는 것도 가능)

## 5. 어떻게 켜나 (계정·API 연결이 끝난 뒤)
1. API 연결이 끝나고, 게시물이 2주 이상 쌓이면 켠다.
2. Claude가 **예약 작업**(매주 월요일 오전 7시대, 한국 시간)을 하나 만든다. 매번 새 세션이 열려서:
   - `node 홍보/자동화/post.mjs token` — 토큰 만료 확인(7일 이하면 보고서 맨 위에 경고, 휴대폰 알림)
   - 인스타·유튜브(·스레드) 지표 받기 → 드라이브 시트의 강사 숫자 읽기
   - 보고서 만들기 → 드라이브에 저장 → 요약 알림
3. 예약 작업은 **읽기만** 한다. 게시·삭제는 하지 않는다.
4. 첫 2주는 Claude가 보고서를 만든 뒤 강사가 "숫자 맞는지" 한 번 확인한다(인스타 앱 인사이트, 유튜브 Studio 숫자와 비교).

## 6. 아직 확인할 것
- 스레드 인사이트 세부 지표가 1인 계정에 다 나오는지 — 스레드를 시작할 때 시험.
- 인스타 지표 이름은 자주 바뀐다(2025년에 impressions·plays·profile_views 없어짐) — 첫 수집 때 확인.
- 유튜브 Analytics는 허락(갱신 토큰)에 `yt-analytics.readonly`와 `youtube.readonly`가 함께 들어 있어야 한다(API_연결.md에서 함께 허락하게 해 둠).
