# 문항 작성 지침 (단원별 문항을 쓰는 작업자용)

`기출변형/CLAUDE.md`(분량·형식·저작권)를 먼저 읽는다. 이 문서는 실제로 문항을 쓸 때의 순서와 기준이다.

## 1. 준비 — 단원마다 읽을 것
1. **개념서 단원 내용**: `textbook/content/_<책>/uNN.js`(t1-1·t1-2는 `textbook/content/t1-1.js`·`t1-2.js` 안에 있음) — 본문, 개념 확인, 수능형 문제.
2. **개념 계획**: `textbook/content/_cc/<책>.js` — 개념 01~ 이름·출제 빈도·'이렇게 나온다'. 문항의 `concept` 번호는 여기 번호다.
   개념 이름 목록은 `node -e "import('./기출변형/lib/units.js').then(m=>console.log(m.UNITS['t2-04'].concepts))"`로 볼 수 있다.
3. **기출 분류**: `textbook/참고/기출분류.json`, `기출분석.md` — 이 대단원에서 실제로 나온 유형.
4. **기출 원문(글자 추출본, 저장소 밖)**: 작업 지시에 적힌 scratchpad `txt/` 폴더의
   `2028-수능-예시문항-통합사회-문제.txt`, `2025년-…`·`2026년-…-문제.txt`와 `-해설.txt`.
   해당 단원 문항을 찾아 **유형·평가 요소·함정**을 파악한다(문장은 옮기지 않는다).
5. **시중 문제집 해설(사실 확인용)**: 같은 폴더의 `개념풀…해설`, `수능풀 통합사회_정답과 해설`, `EBS_개념완성…정답과해설`, `개념풀통합사회2정답…`.
   선지 판단의 근거(사상가 입장, 제도 내용)를 대조하는 데만 쓴다.

## 2. 문항 구성
- 단원 문항 수는 `참고/배분.json`. 난이도는 1차 하 10 · 중 35 · 중상 35 · 상 20%(반올림), 2차 하 0~5 · 중 15 · 중상 45 · 상 35~40%.
- 개념서의 개념을 고르게 다루되, 출제 빈도가 높은(★★★) 개념에 문항을 더 준다. ★ 개념도 최소 1문항.
- 형식을 섞는다: 단순 "옳은 것은?" 만 늘어놓지 않는다. 단원마다 아래 중 여러 가지가 들어가게.
  - 자료 제시(글·대화·사례·사료), **<보기> ㄱ~ㄹ 고르기**(선지는 `'ㄱ, ㄴ'` 꼴 5개), **갑·을·병 입장/사상가 비교**,
    **표(질문 분류표: A~C에 들어갈 질문, 예/아니요)**, **그래프**(막대·꺾은선·원·산점도·방사형·인구 피라미드·기후 그래프), **지도**,
    벤 다이어그램(A·B·C 영역), 채점 결과 역추론, 밑줄 ㉠~㉣ 설명, "적어도 한 사람이 긍정할 진술" 등
  - 지리 단원(통합사회1 Ⅲ·Ⅴ, 통합사회2 Ⅳ·Ⅴ)은 그래프·지도 문항을 단원 문항의 30% 이상.
- 정답 번호 ①~⑤가 단원 안에서 고르게(차이 2 이내). 정답을 다 쓴 뒤 세어 보고 선지 순서를 바꿔 맞춘다.
- `id`: `<단원키>-<차수>-<세 자리>` 예) `t2-04-1-007`. `src`: 근거 기출(예: `2026.9 고2 12번 유형`, 기출이 없는 개념이면 `수능풀 13강 유형`·`교과 개념`).

## 3. 좋은 문항의 기준
- **정답이 하나**: 정답 선지는 개념서·해설지로 확실히 근거를 댈 수 있어야 하고, 오답 선지는 분명히 틀린 곳이 있어야 한다. 애매하면 고치거나 버린다.
- **오답 선지는 그럴듯하게**: 사상가 입장 바꿔치기, '모두/만/항상'으로 넓히기, 원인·결과 뒤집기, A와 B의 특징 맞바꾸기, 비교 방향(높다/낮다) 바꾸기.
- **난이도**: 하 = 개념 한 가지 바로 묻기 / 중 = 사례에 개념 적용 / 중상 = 자료 해석 + 개념 둘 이상 / 상 = 자료에서 대상을 추론한 뒤 비교, <보기> 복합, 수치 계산, 사상가 셋 비교.
- **해설**: 정답 근거(자료에서 무엇을 보고 무엇을 추론했는지) + 오답 선지마다 틀린 이유(①~⑤, <보기>는 ㄱ~ㄹ 모두).
- **용어**: 교육과정·개념서 표기(문화 상대주의, 사회 계층, 지속가능발전 등). 사상가 이름은 개념서 표기.
- **바뀐 제도**: 예금자 보호 한도 1억 원(2025-09-01부터), 2026년 최저 임금 10,320원, 대구 군위(2023 편입).
- 2028 수능처럼 묻는 말 끝: "~으로 옳은 것은?", "~옳은 것만을 <보기>에서 고른 것은?", "~가장 적절한 것은?", "~적절하지 않은 것은?" 등.

## 4. 저작권 — 기출변형의 뜻
- 살릴 것: 기출의 **유형**(자료 구조, 묻는 방식), **평가 요소**(어떤 개념 구분을 묻는지), 함정의 종류.
- 새로 쓸 것: **문장, 사례(나라·인물·상황), 자료 내용, 숫자, 선지 문장**. 기출·문제집 문장을 그대로 또는 단어만 바꿔 옮기지 않는다.
- 사상가 제시문은 원전의 생각을 새 문장으로 풀어 쓴다(문제집 번역문 금지).
- 실제 통계를 쓰려면 출처를 확인한 값만(`source`에 출처). 그 밖의 숫자는 `source: '가상 자료'`.

## 5. 자료 블록 (개념서 render와 같음, 예시는 `textbook/content/z-gallery.js`, `z-diagrams.js`, 기존 단원의 exam)
- 글: `{ t: 'p', text }` / 대화: `{ t: 'dialog', rows: [['갑', '…'], ['을', '…']] }` / 목록: `{ t: 'ul', items }`
- 표: `{ t: 'table', head: ['질문','A','B'], rows: [[…]], widths: [52,24,24], align: [null,'center','center'] }` (칸 합치기 `{ text, rs, cs }`, 빗금 `cls: 'hatch'`)
- 막대: `{ t: 'chart', kind: 'bar', title, categories: ['갑','을'], series: [{ name, values: [..] }], y: { max, step }, unit, source, note, h: 170, w: 420 }`
  - 그 밖의 kind: `hbar`, `stack100`, `line`(series values 또는 points, `schematic: true`), `scatter`, `pie`, `climate`(월 기온·강수), `radar`, `pyramid` — 형식은 `textbook/lib/figures.js`와 z-gallery를 보고 맞춘다.
- 지도: `{ t: 'map', view: 'world' | [서경,남위,동경,북위], style: 'thematic'|'political'|'terrain', highlight, markers, labels, … }` (`textbook/README.md` '지도')
  - 지도에 A~E를 찍는 문항은 `markers`/`labels`로. 국경은 우리나라 정부 시각(기본값 그대로 쓰면 됨).
- 벤 다이어그램: `{ t: 'venn', a: '갑', b: '을', … }` (z-gallery 참고)
- 2단 편집이라 단 폭이 좁다(약 85mm): 표는 열 4개 이하, 그래프는 `w: 420` 정도, 글 자료는 6줄 안팎.
- 문장 표시: `**굵게**`, `__밑줄__`(밑줄 친 ㉠ 등). `[[ ]]`는 쓰지 않는다(빈칸 기능이라).

## 6. 확인 순서 (단원 하나 끝날 때마다)
1. `node 기출변형/tools/check.mjs 1 <단원키>` — 오류 0, 정답 분포·난이도 확인.
2. `cd 기출변형 && node build.mjs 1 units <단원키> png` — `out/1/png/단원별-<단원키>-학생용/*.png`를 몇 쪽 열어
   그래프·지도·표가 잘리거나 겹치지 않는지, 문제 머리가 두 줄로 꺾이지 않는지 본다.
3. 스스로 다시 풀어 본다: 정답이 하나인지, 해설이 맞는지, 개념 번호가 맞는지.
4. 판단이 갈리는 곳은 `기출변형/참고/검토할점.md`에 한 줄씩(단원키·문항 id·이유) 적는다.
