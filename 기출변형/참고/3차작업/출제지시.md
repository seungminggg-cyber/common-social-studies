# MAXIMIN·1차 모의고사 3차 전면 출제 지시서 (모든 출제 에이전트 공통)

저장소: /workspace/common-social-studies (공개 저장소). 작업 폴더: 기출변형/. 고등학교 통합사회(2022 개정) 수능 대비 실전 모의고사 1회(25문항)를 **전부 새로** 쓴다.
강사(승민T)가 7회 견본을 직접 풀어 보고 승인한 기준을 그대로 따른다. 결과물의 품질 기준은 "평가원 3점·수능 3점급 문항이 8개 들어 있는, 정답이 하나로 확실한 시험지"이다.

## 1. 먼저 읽을 것 (순서대로)
1. `기출변형/CLAUDE.md` — 문항 형식, 저작권, 표시 규칙
2. `기출변형/참고/3차지침.md` — **이번 작업의 기준**(배점, 수능 3점급 조건, 평가원 과목별 3점 패턴, 형식 목표, 6절 강사 검수 규칙)
3. `기출변형/참고/문항작성지침.md`, `기출변형/참고/2차지침.md` — 해설·보충 설명 쓰는 법
4. `기출변형/content/2/mock/m7.js` — **견본(강사 승인)**. 문항 모양, 자료 블록 쓰는 법, explain·note 문체를 이것과 같게
5. 내가 맡은 회차의 설계표 JSON(프롬프트에 경로가 있음) — 문항마다 id·unit·points·level, 근거 평가원 기출(seed)
6. `기출변형/참고/평가원기출/과목별요약.md` — 과목별 3점 문항 함정·형식

## 2. 설계표 지키기
- 문항 순서·id·unit·points·level은 설계표 그대로(배점 1.5점 8 · 2점 9 · 2.5점 8 = 50점). 2.5점은 모두 '상', 2점은 '중상', 1.5점은 '중'(1번만 '하').
- seed는 그 문항의 근거로 쓸 평가원 기출(형식·평가 요소). 원문은 `/home/user/자료/평가원3개년/txt/`에 있다(파일 이름에 학년도·시험·과목, '-문제.txt'와 '-정답.txt'. '2025년-9월-고3-모의고사'는 2026학년도 9월 모평). 형식과 평가 요소만 살리고 **문장·자료·사례·숫자는 모두 새로** 쓴다(원문 문장 옮기기 금지).
  - seed가 통합사회 범위를 벗어나는 부분(outside)은 통합사회 개념으로 바꾼다. seed가 맞지 않으면 같은 단원의 다른 평가원 기출(`참고/평가원기출/겹침목록.json`) 또는 학평·2028 예시 유형(`textbook/참고/기출분류.json`, `기출분석.md`)으로 바꿔도 된다. seed가 없는 문항은 학평·예시 유형을 근거로 한다.
  - 다른 회차 출제자들이 동시에 다른 seed로 쓰고 있다. 설계표에 없는 평가원 문항을 새 seed로 쓸 때는 겹침목록에서 내 단원 것만 고른다.
  - `src`에 근거를 적는다(예: '2026학년도 수능 생활과 윤리 15번 형식(…)').
- `concept`는 개념서 개념 번호(`textbook/content/_cc/<책>.js`의 '개념 NN', 단원별 concepts 목록). `type`은 CLAUDE.md의 유형 이름.

## 3. 회차 전체 목표 (3차지침 3절)
- 사상가 4~5(그중 예/아니요 순서도 `diagram kind 'yesno'` 또는 벤 다이어그램 1), 그래프 4~5(막대·꺾은선·원/도넛·띠(stack100)·산점도/거품·인구 피라미드·편차(climdev)·방사형 중 **서로 다른 모양**), 지도 2(세계·우리나라·서울), 계산 2, 질문 분류표·응답표(학생 O/X)·채점 결과 2, 사료·문서·헌법 조항·신문 기사 밑줄 2, 수업 장면·대화·학생 답안 2, '옳지 않은 것' 발문 1~2, 단원 결합형 2 이상. 통합사회1만 / 통합사회2만인 회차는 그 범위 안에서 최대한 맞춘다.
- 1번은 통합적 관점 문항(t1-01/t1-02)이거나 그 회차 첫 단원 문항 — 형식은 7회와 다르게.
- **정답 번호 ①~⑤ 각 5개**, 같은 번호 세 번 연속 금지, 눈에 띄는 규칙(1·2·3·4·5 반복 등) 금지.
- 2.5점(상) 8문항은 3차지침 2절 '수능 3점급 조건' 6개 중 **셋 이상**(판별이 먼저, 두 자료 결합, 2단계 계산·비교, 판단 구조, 정교한 함정, 단원 결합). 2점도 둘 이상.
- '교과서 밖 사실 지식'(순위·연도 세부·최대 수출국 등)만으로 갈리는 선지 금지. 필요하면 자료 안에 단서를 준다.

## 4. 강사 검수에서 정한 규칙 (반드시)
- <보기> ㄱ~ㄹ은 그림의 A·B·C 순서대로(순서도·벤 다이어그램에서 'A에 들어갈…'을 고를 때). 선지는 평가원 표준 조합(① ㄱ, ㄴ ② ㄱ, ㄷ ③ ㄴ, ㄷ ④ ㄴ, ㄹ ⑤ ㄷ, ㄹ 또는 세 개 조합 포함 형식).
- 학생 고르기 선지에서 세 명 조합은 ④·⑤에(① 갑, 을 ② 을, 병 ③ 병, 정 ④ 갑, 을, 정 ⑤ 갑, 병, 정처럼 두 명 → 세 명).
- 계산 공식(부양비·노령화 지수·기회비용·순편익·교환 비율·생태 발자국 등)은 **문제에 준다**(발문 괄호나 자료 안 표·글). 공식 암기로만 풀리게 하지 않는다.
- 사상가: 개념서 사상가 카드 범위 안에서만. **테일러·레건·아퀴나스는 오답 선지로도 쓰지 않는다**. 요나스·왈처·베카리아는 써도 된다. '헌정 체제'처럼 교과서에 드문 말은 쉬운 말로.
- 지도 문항: 세계 지도엔 적도선(`parallels: [{ lat: 0, label: '적도(0°)', size: 12 }]`), 지점은 작은 점(`r: 4.2, size: 15`)으로 정확한 좌표에. 선지는 '지점 ↔ 자료' 대응을 판단해야만 풀리게(자료만 읽어도 풀리는 선지 금지). 지도 w 420·h 210 정도.
- 분배의 '업적'은 이룬 결과·성과(완성한 결과물, 실적)로. 시간·노력과 헷갈리게 하지 않는다.
- 발문에 '가상 사례', '(새로 씀)', '(가상 자료)', '(실제 … 단순화)', 출처를 쓰지 않는다(빌드가 source를 빼지만 처음부터 쓰지 말 것). 실제 통계를 쓰면 `source: '자료: …'`만 적는다(해설 끝으로 자동 이동). 실제 숫자는 출처가 확인된 것만, 나머지는 그럴듯한 가상 숫자.
- 밑줄은 `__밑줄__`, 굵게 `**굵게**`. '옳지 않은 것'의 '않은' 밑줄은 빌드가 자동으로 넣으므로 직접 넣지 않는다.
- 자료의 글쓴이 줄은 `{ t: 'p', right: true, text: '— …의 글' }`.

## 5. 자료 블록 (개념서 render가 아는 것만)
p(text, right), ul, ol, dialog(rows [[이름, 말]]), table(head, rows, widths, align, title, note), chart(kind: bar·hbar·stack100·line·scatter(+bubble)·pie(+donut: true)·climate·climdev·radar·pyramid; categories/series 또는 points 등), map(view 'world' 또는 [서, 남, 동, 북], markers, parallels, routes, arrows, highlight, labels, legend, subregions 서울 자치구), venn(left·right·both, 세 원은 기존 예 참고), diagram(kind 'yesno' 등 — `textbook/lib/diagrams.js`), figrow(items 여러 그림 나란히).
- 예시: `기출변형/content/2/mock/m7.js`, `기출변형/content/2/*.js`, `textbook/content/z-gallery.js`, `textbook/content/z-diagrams.js`. 옵션은 `textbook/lib/figures.js`(KINDS), `maps.js`, `diagrams.js` 머리 주석과 코드에서 확인.
- 그림 하나 미리 보기: 임시 파일 `export default { blocks: [ { …그림 블록, title: 'X' } ] }`을 scratchpad에 만들고 `cd textbook && node tools/figprev.mjs <파일> X <저장.png> 330`.
- 문제집 단 폭은 약 88mm. 그래프 w는 330~420 정도, 글씨가 5pt 아래로 작아지지 않게(page-check가 잡음). 범례 이름은 짧게.

## 7. 해설
- explain: 정답 근거 → 오답 선지(①~⑤)·<보기>(ㄱ~ㄹ)마다 틀린 이유. 계산은 과정까지. 7회 문체('-이다/-한다').
- note: 개념서 밖 내용, 헷갈리는 함정의 원리, 계산 요령.

## 8. 파일 쓰기와 검사
- 맡은 회차 파일 하나만 통째로 다시 쓴다: 2차는 `기출변형/content/2/mock/m<n>.js`, 1차는 `기출변형/content/1/mock/m<n>.js`. 맨 위 주석(구성·형식·근거)은 7회처럼. `no`, `range`, 문항 id·unit은 그대로.
- **다른 파일은 고치지 않는다**(도구·렌더러·다른 회차·개념서 모두). 커밋하지 않는다. 임시 파일은 scratchpad에.
- 검사(모두 `기출변형` 폴더에서):
  - `node tools/check.mjs <차수> mock` — 오류 없음, 내 회차 정답 5·5·5·5·5
  - `node tools/explain-check.mjs <차수> --ids <내 회차 id들 쉼표로>`
  - `node tools/dup-check.mjs 2 --src /home/user/자료/평가원3개년/txt` (1차 회차는 `node tools/dup-check.mjs 1 --vs 2` 도) — 내 문항이 걸리면 고친다
  - 쪽 빌드: `MX_ONLY=<n> MX_NOANS=1 MX_NAME=w<차수>-<n> node build.mjs <차수> mock mx` → `out/<차수>/w<차수>-<n>.pdf`(속표지·차례·간지 3쪽 + 문제 쪽). 문제 쪽이 **7~8쪽**이면 좋다.
  - `node tools/page-check.mjs <차수> w<차수>-<n>` — 내 문항의 [잘림]·[겹침]·[작은글씨]·[넘침]은 고친다
  - `pdftoppm -r 80 -png out/<차수>/w<차수>-<n>.pdf <scratchpad>/w<n>` 로 쪽 그림을 만들어 그림·지도·표가 제대로 나왔는지 **눈으로** 확인한다.
- 다 쓴 뒤 **자기 문항을 처음 보는 사람처럼 다시 풀어** 정답이 하나인지, 근거가 개념서 범위인지 확인한다.
