# MINIMAX 단원 문항 규칙 정리 — 작업 지시서

저장소 /workspace/common-social-studies, 폴더 기출변형/. MINIMAX 기출분석 통합사회1·2(합본)의 **단원 문항**(1차 `content/1/t?-??.js` = STEP 1 기본, 2차 `content/2/t?-??.js` = STEP 2 심화)에, 강사가 MAXIMIN 7회를 검수하며 정한 규칙을 적용한다. **문항을 새로 쓰는 일이 아니다** — 규칙에 어긋난 곳만 최소한으로 고친다(전면 수정은 강사 검수 뒤 따로 함).

먼저 읽을 것: `기출변형/CLAUDE.md`, `기출변형/참고/3차지침.md`의 6절(강사 검수 규칙). 개념서(범위 확인): `textbook/content/`(t1-1.js, t1-2.js, _t1-3~5/u05~u14.js, _t2-1~5/u01~u16.js).

## 맡은 문항 목록
프롬프트의 `작업-<묶음>.json` = { 문항 id: [걸린 항목, …] }. 항목별로 아래처럼 처리한다.

1. **금지사상가 / 해설에 금지 사상가** (테일러·레건·아퀴나스): 문제 글·선지·<보기>에서 이 사상가나 그 사상가만의 주장(테일러: 목적론적 삶의 중심 / 레건: 삶의 주체, 동물 권리 / 아퀴나스: 자연법·신앙과 이성 등)을 쓰지 않게 바꾼다. 오답 선지라도 범위 안 사상가(개념서 카드: 슈바이처, 싱어, 칸트, 레오폴드, 베이컨, 데카르트, 아리스토텔레스, 에피쿠로스, 스토아, 공자·맹자·노자·장자·석가, 벤담·밀, 롤스·노직, 샌델·왈처·매킨타이어, 요나스, 베카리아 등)의 주장으로 바꾸고, 해설·보충 설명에서도 그 이름을 지운다. 정답이 바뀌지 않게 하는 것이 좋다.
2. **보기 순서 / 보기 순서 의심**: <보기> ㄱ~ㄹ이 그림·자료의 A·B·C(또는 (가)·(나)·(다), 갑·을) 순서가 되게 다시 놓는다. 두 대상을 비교하는 보기('(가)는 (나)보다 …')는 맨 뒤에 와도 된다(그건 위반 아님 — 이미 순서가 맞으면 손대지 않는다). 순서를 바꾸면 선지 조합(ㄱ, ㄴ …)·정답·해설의 ㄱ~ㄹ 표기를 함께 고친다. 선지는 평가원 표준 조합(① ㄱ, ㄴ ② ㄱ, ㄷ ③ ㄴ, ㄷ ④ ㄴ, ㄹ ⑤ ㄷ, ㄹ 또는 세 개 조합 포함)으로.
3. **세명조합위치**: 학생 고르기 선지에서 두 명 조합을 ①~③, 세 명 조합을 ④·⑤에 둔다(예: ① 갑, 을 ② 을, 병 ③ 병, 정 ④ 갑, 을, 정 ⑤ 갑, 병, 정). 정답·해설 번호도 고친다.
4. **공식없음**(계산 문항): 계산에 필요한 공식을 발문 끝 '(단, … = … 이다.)'나 자료 아래 note로 짧게 준다(예: 기회비용 = 명시적 비용 + 암묵적 비용, 순편익 = 편익 − 기회비용, 부양비·노령화 지수, 단리·복리, 수익률, 비교 우위의 기회비용, 생태 발자국, 도시화율, 성비 등). 공식이라 할 것이 없는 단순 셈이면 건너뛰고 보고에 '공식 불필요'로 적는다.
5. **쪽검사** (작은 글씨·잘림·겹침·쉼표·넘침): 그 문항의 그림 블록 설정을 고친다(그래프 w를 줄이면 단 폭에 맞춰 글씨가 커짐, 범례 이름 짧게, 이름표 위치 옮기기, 연도 축에 쉼표가 찍히면 숫자 형식 옵션·문자열로, 지도 legendSize·size 등). 렌더러(`textbook/lib/*`)·CSS·build.mjs는 **고치지 않는다**. 여러 문항에 같은 원인(예: 기후 그래프 '(월)' 글자)이 있어 문항 설정으로 못 고치면 보고에 적는다(조정 담당이 한꺼번에 고침).
   - 그림 하나 미리 보기: 임시 파일 `export default { blocks: [ { …그림 블록, title: 'X' } ] }`을 scratchpad에 만들고 `cd textbook && node tools/figprev.mjs <파일> X <저장.png> 330`. (모의고사와 달리 단원 문항은 그림을 88%로 줄이지 않는다.)

## 지킬 것
- 문항 id·단원·난이도·개념 번호는 그대로. **맡은 단원 파일만** 고친다(다른 묶음 담당 3명이 다른 단원을 동시에 고친다). 커밋하지 않는다.
- 정답 번호를 바꿨으면 그 단원 파일 안에서 ①~⑤가 고르게(`node tools/check.mjs <차수> <단원키>`가 분포를 보여 줌) — 크게 치우치면 다른 바꾼 문항의 선지 순서로 맞춘다.
- 해설(explain)은 오답 선지·<보기>마다 이유가 있게, 바뀐 기호에 맞게.
- 출처·'가상 자료' 표시는 빌드가 자동으로 빼므로 손대지 않아도 된다.

## 검사 (기출변형 폴더에서)
- `node tools/check.mjs 1` · `node tools/check.mjs 2` — 오류 없음
- `node tools/explain-check.mjs 1 --ids <바꾼 1차 id들>` · `node tools/explain-check.mjs 2 --ids <바꾼 2차 id들>`
- `node tools/note-check.mjs`
- 책 전체 빌드는 하지 않는다(조정 담당이 마지막에 한 번 빌드하고 쪽 검사를 다시 돌린다). 그림은 figprev로 확인.
- 바꾼 문항은 처음 보는 사람처럼 다시 풀어 정답이 하나인지 확인한다.
