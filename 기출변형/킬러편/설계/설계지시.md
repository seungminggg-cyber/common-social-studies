# 킬러편 설계 카드 만들기 — 설계 에이전트 지시서

저장소: `/workspace/common-social-studies`(공개 저장소). 작업 폴더: `기출변형/`.

## 배경
승민T(학원 강사)가 「MINIMAX 킬러편」을 만든다. 2028 수능 통합사회 대비 최고 난도 문항 200개짜리 책이다. 문항은 나중에 Fable 모델이 쓴다. 우리는 Fable이 바로 쓸 수 있도록 **중단원별 설계 카드**를 만든다. 설계 카드는 출제자에게 주는 **재료와 제안**이다. 형식을 하나하나 못 박는 지시가 아니다. 강사는 Fable이 스스로 생각해서 다양한 신유형·이중추론 문항을 만들기를 바란다. 그래서 형식은 '제안'으로 적고, 소재와 근거 기출을 넉넉하게 준다.

## 먼저 읽을 것
1. `기출변형/킬러편/기준.md` — 이 책의 기준(난이도, 이중추론, 형식 목표, 스킬 태그). **가장 중요하다.**
2. `기출변형/참고/3차지침.md` 2·2-1·6절 — 평가원 3점 패턴, 강사 규칙
3. `기출변형/특강/content/analysis.js` — 2028 예시문항 25문항 분석(7유형)
4. `textbook/참고/기출분석.md` — 학평 경향
5. 맡은 중단원의 개념서: 아래 표 참고. 개념 번호·이름·출제 빈도는 `기출변형/lib/units.js`가 읽는 `textbook/content/_cc/`에도 있다.
   - 통합사회1: t1-01·02 → `textbook/content/t1-1.js`, t1-03·04 → `t1-2.js`, t1-05~07 → `_t1-3/u05~u07.js`, t1-08~11 → `_t1-4/u08~u11.js`, t1-12~14 → `_t1-5/u12~u14.js`
   - 통합사회2: t2-01~03 → `_t2-1/u01~u03.js`, t2-04~06 → `_t2-2/u04~u06.js`, t2-07~10 → `_t2-3/u07~u10.js`, t2-11~13 → `_t2-4/u11~u13.js`, t2-14~16 → `_t2-5/u14~u16.js`
6. 근거 기출 찾기: `기출변형/참고/평가원기출/겹침목록.json`(1,440문항 요약, unit·concepts·format·data·topic·trap·adapt·overlap·level). 맡은 단원만 걸러 보라. 예:
   `node -e "const j=require('./기출변형/참고/평가원기출/겹침목록.json');for(const q of j['문항'])if(q.unit==='t2-08'&&q.overlap!=='없음')console.log(q.exam,q.subject,q.no,q.points,q.level,q.overlap,'|',q.format.join('/'),'|',q.topic,'|',q.trap)"`
7. 이미 쓴 씨앗: `기출변형/킬러편/설계/쓴씨앗.json`. 여기에 있는 **평가원 선택과목 기출**(시험·과목·번호가 같은 것)은 씨앗으로 쓰지 않는다. 2028 예시문항과 학평은 이 책의 뼈대·경향이라 쓴씨앗에 있어도 형식 근거로 쓴다(같은 자료·사례·숫자만 피함). (2026-11-15 바로잡음)
8. 원문이 꼭 필요하면 `/home/user/자료/통합사회/txt/`(글자본)를 볼 수 있다. 다만 원문 문장을 옮기지 않는다.

## 만들 것
맡은 중단원마다 파일 하나: `기출변형/킬러편/설계/<중단원키>.json`. 문항 수는 `기출변형/킬러편/배분.json`을 따른다.

```json
{
  "unit": "t2-08",
  "title": "중단원 이름",
  "count": 9,
  "재료": {
    "판별단서": ["숨겨서 찾게 할 대상과 그 단서 (예: 롤스 — 원초적 입장·무지의 베일·최소 수혜자)"],
    "헷갈리는짝": ["학생이 자주 섞는 개념·사상가 짝과 차이 한 줄"],
    "함정": ["이 단원에서 쓸 만한 정교한 함정 (평가원 trap에서 가져와 통합사회 내용으로)"],
    "자료형식": ["이 단원에 어울리는 자료 모양 (그래프 종류, 표, 순서도, 지도 등)"],
    "결합후보": ["다른 중단원과 묶을 만한 주제 (예: t2-06 공간 불평등 + t2-08 정부의 역할)"]
  },
  "slots": [
    {
      "id": "t2-08-k-001",
      "concept": [3, 5],
      "focus": "무엇을 평가하는가 (한두 문장)",
      "kform": "형식 제안 (예: 채점 결과 역추론 + 표 계산)",
      "double": "이중추론 제안 (예: 채점 점수 → 학생 응답 → 합리적 선택 여부)",
      "kcond": [1, 3, 4, 5],
      "skill": "S06",
      "seeds": [ { "exam": "2026학년도 수능", "subject": "경제", "no": 12, "use": "이 기출에서 가져올 구조·함정" } ],
      "type": "계산",
      "answerHint": "정답 방향이나 핵심 함정 한 줄(선택)"
    }
  ]
}
```

## 기준
- `concept`는 그 중단원의 실제 개념 번호(개념서 '개념 NN'). `type`은 `기출변형/CLAUDE.md`의 11가지 유형 이름 중 하나. `skill`은 `기준.md` 7절의 키.
- 모든 slot은 `기준.md` 2절의 조건을 셋 이상 갖출 수 있게 설계하고, **이중추론**이 들어가게 한다.
- 한 중단원 안에서 형식·소재가 겹치지 않게 하고, 출제 빈도가 높은 개념(★★★)을 먼저 다룬다. 다만 한 개념에 몰지 않는다.
- 슬롯마다 근거 기출을 1~2개 단다. 평가원 겹침목록에서 overlap '완전'을 먼저, '부분'은 범위 밖 요소를 바꿀 방법을 `use`에 적는다. 맞는 평가원 문항이 없으면 2028 예시문항 번호나 학평 문항으로 근거를 대도 된다(예: `{ "exam": "2028 수능 예시문항", "no": 15, ... }`).
- 신유형을 적극적으로 제안한다(순서도, 질문 분류표, 수행평가 채점 결과, 학생 O/X 응답표, 상댓값 지수 그래프, 조건 여럿 퍼즐 등). 그러나 내용은 반드시 개념서 범위 안이다.
- 사상가는 개념서 사상가 카드 범위 안에서만 쓴다. 테일러·레건·아퀴나스는 쓰지 않는다. 요나스·왈처·베카리아는 써도 된다.
- 단원 결합 슬롯은 맡은 범위 안에서 1~2개쯤 넣는다(다른 대단원과 묶어도 된다).
- **문항 본문(제시문·선지)은 쓰지 않는다.** 설계만 한다.

## 마칠 때
- JSON 파일이 `node -e "JSON.parse(require('fs').readFileSync('<파일>','utf8'))"`로 읽히는지 확인한다.
- 다른 파일은 고치지 않는다. 커밋하지 않는다.
- 보고(한국어, 짧게): 중단원별 슬롯 수, skill 분포, 형식 분포, 씨앗을 못 찾은 슬롯, 확신이 낮은 점.
